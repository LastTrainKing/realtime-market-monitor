## 一、这是什么 / 适用场景

本项目把「全市场板块 / 概念的资金流向」整理成可读的盘中视图：主力资金累计曲线、
板块辨识度榜、题材聚簇、主角更替、阶段对比、开盘节点检测、个股异动等。
起点是复刻某财经短视频账号展示的**分析能力**（盘中资金流曲线 + 板块辨识度量化 +
选手式解读），而不是复刻视频本身。

适用场景：

- 学习 Qt / PySide6 桌面应用的工程组织与性能优化（增量渲染、blit、延迟加载）；
- 学习高频行情采集的工程问题（连接复用、限流、熔断、退避、缺口处理）；
- 研究「数据层有序 ≠ 屏幕有序」这类跨层缺陷的验证方法；
- 复盘一个真实项目从 HTML 看板 → Android → 原生桌面 → Tauri 重写的演进过程。

**不适合**：作为实盘交易依据、作为行情数据的权威来源、或用于任何形式的自动交易。

## 二、两条独立的产品线

仓库里有两套**互不继承**的实现。它们解决的问题相近，但技术栈、版本号体系、
目录结构完全独立 —— **不要把它们的版本号当成同一条版本链**。

| | `FlowLiveNative`（原生版） | `CapitalFlowCommandCenter`（指挥中心） |
|---|---|---|
| 目录 | [`flowlive-native/`](flowlive-native/) · [`legacy/`](legacy/) | [`command-center/`](command-center/) |
| 技术栈 | Python 3.13 + PySide6 + matplotlib + numpy | Tauri 2 + Rust(Axum) + React 18 + TypeScript + ECharts |
| 版本区间 | v1.2.5 → **v3.0.6** | 前身 v4.0.0 → v1.0.0 → **v1.1.0** |
| 开发时间 | 2026-09-17 ~ 2026-09-23 | 2026-09-25 ~ 2026-10-02 |
| 打包形态 | PyInstaller onedir（exe + `_internal/`） | NSIS 安装包 + 便携目录 |
| 版本号规则 | `MAJOR.MINOR.PATCH`，**满 9 进 1**（`3.0.9` 之后是 `3.1.0`，不出现 `3.0.10`） | 常规语义化版本 |

**为什么分成两条线**：指挥中心不是原生版的升级，而是换语言、换架构的重新实现。
它的 `v4.0.0` 是前身原型（Tauri 1 + WebView2，主程序名 `MyApplication.exe`），
重写后版本号从 `1.0.0` 重新起算 —— 所以同一个仓库里会同时出现 `v3.0.6` 和 `v1.1.0`，
它们**没有先后关系**。

## 三、主要功能与技术架构

### 3.1 功能（以 v3.0.6 源码为准）

原生版是 **6 个母模块 + 14 个子模块 + 40 个面板** 的两级结构（v2.1.0 起重构）：

| 母模块 | 子模块 | 内容 |
|---|---|---|
| 总览 | —（单页） | 6 张指标卡 + 主力资金累计曲线（末端标签 / 悬停联动 / 高亮弱化分层） |
| 大盘 | 市场全景 · 开盘检测 | 指数分时、流入流出对比、区间极值（吸筹/出货前十）；09:36/09:41/09:46 三节点板块与个股 Top5 |
| 个股 | 个股异动 · 个股精选 | 九张 Top10 表（量比/成交量/主力净流入 × 三节点）；九榜上榜次数统计 |
| 资金排行 | 异动雷达 · 辨识度榜 · 行业概况 · 实时榜单 | 板块辨识度五维加权、行业资金流、实时榜单累积池 |
| 板块题材 | 题材聚簇 | 主线聚类、龙头领先反应、相对长度柱条 |
| 盘中复盘 | 实时事件 · 主角更替 · 阶段对比 · 关键节点 | 全天关键节点榜（按时间先后）、主角更替、阶段对比 |

### 3.2 代码结构（原生版）

```
flowlive-native/build/
├── app_main_v203.py          # 主程序（约 503 KB / 单文件，v3.0.6 时 VERSION="3.0.6"）
├── core/                     # 分析内核与数据层
│   ├── flowdata.py           # 全市场板块分时资金流抓取 + 面板落盘（约 124 KB）
│   ├── salience.py           # 辨识度五维加权、主线聚类、关键节点（约 47 KB）
│   ├── source.py             # 多源注册与能力声明（东财 / 腾讯）
│   ├── opensnap.py           # 定点全市场快照（板块 ~1000 + 个股 ~5900）
│   ├── tradingtime.py        # 交易时段判定（盘中/午休/盘后/休市）
│   ├── tradecal.py           # 交易日历（磁盘优先）
│   ├── backfill.py           # 日级资金流历史补全
│   ├── watchlist.py          # 实时榜单累积池（只增不减）
│   ├── leader.py             # 龙头领先反应（点火/跳水拐点）
│   ├── universe.py           # 板块池清洗（剔除统计桶与层级重复）
│   ├── store.py / archive.py # 存储与 30 交易日滚动归档
│   └── server.py             # 本地 HTTP 服务（供浏览器看板形态复用）
├── core2/tradecal.py         # 同名覆盖副本（构建时覆盖 core/tradecal.py，两份必须同步）
├── tools/                    # 部署、诊断、打包辅助脚本
├── 资金流向原生版_v30x.spec   # PyInstaller 打包配置（v2.0.1 ~ v3.0.6 逐版保留）
└── test_*.py / verify_*.py   # 离线验证脚本
```

**四份实现 / 六个副本的同步纪律**：同一套分析逻辑在历史上存在 4 份实现
（`core/salience.py`、打包产物内的副本、命令行工具副本、JS 重写版）。
改一处必须同步全部 —— 这是项目里反复踩到的坑，已写进 `docs/archive-2026-09-21/`。

### 3.3 技术要点（有实测依据的部分）

- **onedir 打包而非 onefile**：onefile 每次启动要把约 69 MB 包解到 `%TEMP%\_MEIxxxx`，
  实测多 1.64 s；onedir 预先摊开。
- **图表增量渲染**：`FanChart` 整幅重绘 92.03 ms → 增量更新 1.18 ms（约 78×）；
  `IndexChart` 65.82 ms → 1.44 ms（约 46×）。任一条件不满足即回退整幅重绘。
- **悬停标签带**：右端标签改用 Qt 覆盖层（`QPainter` 重画 20 条 < 0.5 ms），
  换分钟全周期 154 ms → 0.27 ms 均值。
- **跨分钟守卫**：数据源是分钟粒度，同一分钟内重复请求拿到同一值；
  记住上次真实抓取的交易分钟，同分钟直接跳过 → 无论定时器设 1 s 还是 10 s，
  每分钟真实抓取恒为 1 次。
- **面板「不降级」守卫**：同一交易日取到的板块数不足本地已有的 60% 时保留本地面板，
  避免限流导致面板被截断后特征层塌陷。

> 以上数字来自项目自带的验证脚本与开发日志（`docs/archive-2026-09-21/更新日志.md`），
> 属于**作者当时的实测记录**，本次归档未重新跑通全部用例（见第十二节）。

## 六、安装、运行与构建

> 完整步骤见 [docs/installation.md](docs/installation.md)。以下为最小路径。

### 6.1 运行网页版看板（最轻）

```bash
cd web-dashboard
python serve.py          # 或双击「启动看板.bat」，浏览器会自动打开
```

纯标准库，无第三方依赖；只监听 `127.0.0.1`。**注意**：页面会直接从浏览器
请求东方财富接口，请求来源是**你自己的 IP**。

### 6.2 从源码运行原生版

```bash
cd flowlive-native/build
python -m venv .venv
.venv/Scripts/pip install PySide6 matplotlib numpy
.venv/Scripts/python app_main_v203.py
```

### 6.3 构建 onedir 发布包

```bash
cd flowlive-native/build
# ★ 必须用专用 venv，且 spec 里的 excludes 不能删
.venv/Scripts/python -m PyInstaller 资金流向原生版_v306.spec --noconfirm
```

构建要点（来自 spec 注释，都是踩过的坑）：

1. **onedir 而非 onefile**：onefile 每次启动要解包约 69 MB。
2. **`datas` 必须含 `app.ico`**：`EXE(icon=...)` 只管文件图标，运行期
   `setWindowIcon` 需要 `_MEIPASS` 下有真实 ico。
3. **`excludes` 必须显式拉黑 `pandas` / `lxml` / `fsspec`**：打包环境不干净时，
   matplotlib 的可选依赖会把 pandas 拖进来（实测 69.6 MB → 92.5 MB）。
4. **部署时 exe 与 `_internal/` 必须成对更新**，只换 exe 会得到「新程序 + 旧依赖」。
5. **打包前清 `core/__pycache__`**：`app_main_v203.py` 把 `core/` 插入 `sys.path`，
   源码与 `.pyc` 版本不匹配时会静默加载旧逻辑。

### 6.4 构建指挥中心

见 [`command-center/README.md`](command-center/README.md) 与
`command-center/docs/DEVELOPMENT.md`（Rust + Node + Tauri CLI 工具链）。

## 八、行情数据来源

（详见 [docs/data-source-risk.md](docs/data-source-risk.md)）：

- 2026-09-23 盘前，对 `push2` 做「每 20 秒一个请求」的低频探测，
  **45 次中仅放行 10 次（22%）**，其余全部 `RemoteDisconnected`（约 130 ms 快速拒绝）。
- 同日 16:55 收盘后复测：`push2` / `push2delay` / `push2his` **全部**拒绝连接，
  而 `baidu.com` 正常返回 200 —— 是目标站对该 IP 的限制，不是本地网络故障。
- 该 IP 受限期间，一次全量抓取只取到 122 个板块（正常约 1000 个）就写盘，
  导致当天的面板数据被永久截断且**不可恢复**（分钟接口只提供最近一个交易日）。

**作者在事件后的处理方式**（可作为使用者的参考）：把刷新频率从秒级降到**分钟级**、
引入自适应并发与熔断、默认改用替代源、并保留切回东方财富的开关。
即便如此，也**没有**、也**不能**保证不会再次被限流。

## 十、虚拟机隔离运行建议

1. 优先在**独立 Windows 虚拟机**内安装、测试和长期运行，与日常主机隔离。
2. 虚拟机内**不要**存放主机的个人凭据、无关敏感文件或真实账户密钥。
3. 运行前**创建快照**，保留可恢复的初始环境。
4. 仅开放必要的网络、文件共享和剪贴板权限。
5. 记录接口异常、请求失败和数据更新时间，便于排查（本项目自带 `logs/` 与状态栏数据源标记）。
6. **虚拟机不是 IP 屏蔽或接口风控的规避工具**，不能保证避免封禁。
7. **不要**为了验证风险而主动做高频请求、压力测试或其他可能造成实际访问限制的行为。

> 与架构相符的补充：本软件**已实现**分钟级刷新档位（1/2/3/5/10/15 分钟）、
> 跨分钟守卫（每分钟真实抓取恒为 1 次）、AIMD 自适应并发、按域名滑动窗口熔断与
> 全局硬熔断、面板「不降级」守卫。**未实现**（属于待改进项）：请求量配额上限、
> 面向用户的限流可视化面板、跨进程的请求节流。

### 12.2 软件层面的已知限制（来自源码注释与开发日志）

- **分钟级历史不可回溯**：数据源只提供最近一个交易日的分钟数据，更早的需逐日累积。
- **概念层分钟历史缺失**：腾讯替代源没有板块分钟资金流历史，只能逐分钟累积；
  切换后当天概念板块没有曲线（界面会如实断开，不插值、不编造）。
- **09-23 面板永久截断**：该交易日面板被限流截断为 122 列且不可恢复，
  后续只能靠「不降级守卫」防止再发生。
- **`core/` 与 `core2/` 存在同名覆盖副本**（`tradecal.py`），两份必须同步修改。
- **GBK 编码陷阱**：frozen 版 stdout 为 GBK，非 GBK 字符会让日志写入抛
  `UnicodeEncodeError`；已在入口装 `reconfigure(errors="replace")` 兜底。
- **Playwright UI 自动化未执行**（指挥中心）：浏览器二进制下载受限，改用真实安装 +
  窗口级截图验收，报告中已如实标注。

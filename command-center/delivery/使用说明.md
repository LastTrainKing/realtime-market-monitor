# 资金流向指挥中心 AI Edition

> Capital Flow Command Center AI Edition — 面向 A 股交易研究的 Windows 桌面实时盯盘终端

一款普通 Windows 用户**双击即可使用**的桌面软件：安装后自动创建桌面快捷方式，双击进入全屏实时指挥界面，
自动采集、清洗、计算并展示盘中资金行为与市场结构。

---

## 一、最终用户使用方式

```
下载安装包  资金流向指挥中心_1.1.0_x64-setup.exe
        ↓
双击安装（无需任何技术操作，不需要管理员权限）
        ↓
桌面出现快捷方式「资金流向指挥中心」
        ↓
双击快捷方式 → 全屏启动 → 进入实时盯盘界面
```

**用户不需要**：安装开发环境、输入命令、启动后台服务、打开浏览器、修改配置、手动运行脚本。

### 1.1 先确认你装的是哪一版（重要）

界面左上角品牌区会显示**当前后端实际运行的版本号**，例如：

```
资金流向指挥中心
Command Center  v1.1.0
```

排查问题前请先看这个数字：

| 你看到的版本 | 说明 |
| --- | --- |
| `v1.1.0` | 当前版本（股票池只有一个全市场池，不存在"活跃股样本"） |
| `v0.1.0` | **旧版本**（2026-10-01 的首版）。它仍然使用 1200 只的"活跃股样本"，首页也还是"市场全景"旧布局 —— 请重新安装新安装包 |

> 这个版本号不是写死的，它来自后端 `/api/health` 上报的编译版本，
> 因此"界面上显示的版本"就是"实际在跑的版本"。
> 早期版本界面上不显示版本号，曾导致"装的是旧版却在排查新问题"，
> 已修复并加了回归测试。

也可以在文件管理器里核对安装目录（辅助判断方式）：

| 文件 | 新版本（1.1.0） | 旧版本（0.1.0） |
| --- | --- | --- |
| `%LOCALAPPDATA%\资金流向指挥中心\backend\capital_backend.exe` | 约 **48.8 MB**（含 DuckDB 查询层） | 约 **11.5 MB** |

安装新版时请先**退出正在运行的程序**（否则文件被占用可能替换失败），
安装完成后重新从桌面快捷方式启动。

## 二、技术架构

| 层次 | 技术 | 说明 |
| --- | --- | --- |
| 桌面外壳 | **Tauri 2.x** | 只负责窗口管理、生命周期、系统托盘、启动/关闭后端、EXE 封装 |
| 前端 | **React 18 + TypeScript(strict) + Vite** | 只负责渲染、交互、动画、图表；**不含任何业务逻辑** |
| 状态管理 | **Zustand** | 细粒度 selector，避免整页重渲染 |
| 样式 | **CSS + CSS Modules** | Steam Big Picture 风格深色玻璃拟态 |
| 图表 | **ECharts 5** | 增量更新（`setOption` 合并），不销毁重建 |
| 后端 | **Rust + Axum + Tokio + Reqwest + Serde** | 全部业务逻辑唯一归属 |
| 数据库 | **SQLite（rusqlite, WAL）** | 节点快照 / 榜单事件 / 分钟数据 / 用户配置 |
| 日志 | **tracing + tracing-appender** | app / backend / network / error 四类日志分文件 |
| 通信 | **HTTP REST + JSON（127.0.0.1）** | 前后端完全解耦 |

### 进程模型

```
资金流向指挥中心.exe  (Tauri Shell)
        │
        ├── React UI Renderer（WebView2）
        │
        └── backend/capital_backend.exe  (Rust Sidecar，无窗口后台运行)
                  ├── Axum HTTP Server
                  ├── Data Collector（指数 / 个股 / 板块 / 资金 / 历史）
                  ├── Data Processing（清洗 / 归一化 / 异常过滤）
                  ├── Analysis Engine（九榜 / 开盘检测 / 异动 / 精选）
                  ├── Cache System（内存 → SQLite → 历史归档）
                  ├── Scheduler（统一任务调度）
                  └── Error Recovery（限流 / 退避 / 熔断 / 降级 / 冷却）
```

## 四、核心能力

### 4.0 首页四个核心模块

首页由四个模块组成，**全部从本地历史静态分钟库读取**，横轴一律使用
行情数据自带的时间字段（09:31→15:00），不使用程序当前时间：

| 模块 | 数据来源 | 说明 |
| --- | --- | --- |
| ① 指数分时 | 本地历史分钟库 | 以昨收为基准，右轴显示涨跌幅；昨收不可得时退化为绝对点位并明说 |
| ② 主力资金累计曲线 | 本地历史分钟库 | **东方财富现成的大盘资金流接口**（`fflow/kline`，secid=1.000001）。该接口返回的本身就是**累计**值，程序**不做任何累加**。 |
| ③ 主力资金流入流出板块对比 | 盘中：实时缓存并同步落盘<br>非盘中：本地持久化快照 | 界面显示**来源通道**与**板块覆盖数**（行业 / 概念）；覆盖不足时显式告警 |
| ④ 时点数据面板 | 本地历史分钟库 | 与②**同一交易日、同一分钟**；鼠标悬停曲线即可查看该时点 |

**②④ 永不脱节**：曲线的悬停/点击会把分钟抛给面板，面板按同一交易日
同一分钟取数，不存在"曲线画的是 A 日、面板显示的是 B 时点"的错位。

页面顶部另有"数据口径条"，把**系统时间 / 行情时间 / 数据交易日 /
数据模式 / 数据源状态 / 抓取时间**分开显示，避免把历史静态数据误读为实时数据。

> 首页顶部的"指数行情快照"条走实时行情通道，**不属于**上述四个核心模块，
> 界面上已与历史模块明确区分。

### 4.1 实时市场感知

- **指数行情**：上证 / 深证 / 创业板 / 沪深300 / 科创50 / 北证50
- **九榜系统**（完全配置驱动，可随时启停、扩展）：
  1. 主力净流入　2. 主力净占比　3. 成交量　4. 成交额
  5. 量比　　　　6. 换手率　　　7. 涨跌幅　8. 板块净流入　9. 板块涨幅
- **市场概况**：涨跌家数、涨跌停、两市成交额、主力净流入、情绪分
- **资金曲线**：两市主力净流入分时曲线
- **板块资金流**：行业 + 概念共 200+ 板块排名与图表

### 4.2 早盘节点检测（09:35 / 09:40 / 09:45）

每个节点生成：
- **开盘检测**：成交量 Top5、主力净流入 Top5
- **个股异动**：量比 Top10、成交量 Top10、主力净流入 Top10

### 4.3 历史回溯（关键设计）

**解决"程序没开就没有早盘数据"的问题**，三条重建通道：

1. 本机 SQLite 分钟数据（程序运行期间持续落库）
2. 东方财富分钟 K 线（可累计出节点成交量 / 成交额）
3. 腾讯分时接口（直接提供节点累计成交量 / 成交额，自带交易日可校验）

状态严格区分：`AVAILABLE` / `WAITING` / `PARTIAL` / `DATA_SOURCE_LIMITATION` / `UNAVAILABLE`，
指标整体缺失时**隐藏该榜单并说明原因**，绝不展示一排 0 或伪造数据。

### 4.4 九榜统计 · 个股精选

**事件驱动计数**（非刷新计数）：

```
首次进入榜单        → 记 1 次事件
持续停留            → 不重复计数
掉出后再次进入      → 新增 1 次事件
```

### 4.5 数据稳定性设计

| 机制 | 实现 |
| --- | --- |
| 请求限流 | 每秒 / 每分钟 / 最小间隔 / 并发上限 四重令牌桶 |
| 请求去重 | 同一 URL 并发请求合并为一次 |
| 指数退避 | 1s → 2s → 4s → 8s（叠加抖动，避免雪崩） |
| 熔断 | 按主机维度，连续失败进入 Open，冷却后半开探测 |
| 主机轮换 | push2 多镜像自动切换；网络级故障立即停止轮换 |
| 数据源冷却 | 通道整体失败后冷却 180 秒，避免每轮重新超时 |
| 多源降级 | 东方财富 → 腾讯财经 → 新浪财经 → 本地缓存 |
| 分级刷新 | 指数 3s / 板块 10s / 个股 20s / 全市场 90s / 分钟落库 60s |
| 非交易时段 | 自动降频但**不停采**，保证打开即有最近交易日数据 |

### 4.6 真实性与透明度

所有数据均携带三个字段：

```json
{ "value": 128.5, "status": "CACHE", "source": "tencent_realtime", "updated_at": "09:45:20" }
```

界面按状态显示绿（实时）/ 黄（缓存·重建·延迟）/ 红（异常·限制），
并展示数据来源与最后更新时间，**禁止统一显示"暂无数据"**。

## 八、已知限制

1. **东方财富接口的可用性受网络环境影响**。当主通道不可用时，软件自动切换到腾讯 / 新浪通道；
   切换后部分口径（如主力净占比）会按定义推导，板块榜单容量会略小。
2. **历史节点重建的资金流明细**依赖东方财富分钟资金流接口；该接口不可用时，
   成交量与价格仍可完整重建，资金榜会明确标注为"部分重建"并隐藏。
3. **1 分钟历史数据最多只能回溯 4 个交易日**。这是数据源 `datalen` 上限 1023 点
   决定的物理限制，实测各粒度可回溯：1 分钟 4 天 / 5 分钟 21 天 / 15 分钟 63 天 /
   30 分钟 127 天 / 60 分钟 255 天。**90 天的 1 分钟数据物理上不可能**，
   只能靠程序逐日累积；把配置项 `history_granularity` 改为 `30` 可立即获得
   127 个交易日的分钟级覆盖。
4. **板块模块只有"当日定稿快照"，没有板块级分时序列**。数据源不提供历史交易日的
   板块分钟资金流，这一点在接口返回的说明与界面上都已如实标注，未做任何伪造。
5. **板块覆盖数取决于当前通道**。东方财富的概念板块有 **400+** 个；
   降级到腾讯财经时，其榜单接口**单次上限为 200 条**（实测 250 及以上会被服务端直接拒绝），
   因此只能覆盖约 231 个板块。界面顶部会显示"来源通道 + 共 N 个板块（行业 X / 概念 Y）"，
   概念数偏少时给出显式告警，**不会把"只覆盖一部分"当作全量展示**。
6. **"大盘资金流"的覆盖范围（沪市 / 沪深两市）尚未实测确认**。
   接口为东财 `fflow/kline`（secid=1.000001，上证指数）。本机当前对东财 API 的访问
   被网络环境阻断，无法实测该接口返回的是沪市还是沪深两市，因此界面文案只写
   "东财大盘资金流"，不写"两市"，避免给出未经核实的口径。
7. **分钟成交量没有做"大单 / 中单 / 小单"分级**。缺少逐笔成交数据，
   任何此类分级都只能是估算；当前代码中不存在"把分钟成交量伪装成大单"的逻辑。
8. **首页四个核心模块之外的实时行情条依赖行情通道**；通道不可用时该条会显示
   数据源异常，但下方四个历史模块仍可正常从本地读取。
9. **股票池只有一个：全市场**（约 5571 只）。它来自**本地证券列表 + 批量行情**，
   不依赖排行榜分页接口，因此在东方财富被阻断时也能从腾讯 / 新浪取全
   （实测：东财完全不可达时仍拿到 5571/5571、缺失 0）。
   早期版本存在第二个"活跃股样本"池（由排行榜接口拼出，上限 1200 只），
   **已彻底移除** —— 那种池子按成交额 / 换手率排序，属于**有偏样本**，
   用它算涨跌家数、涨停跌停会系统性失真。
   全市场股票池未就绪时，界面显示"扫描进行中"，**不展示任何基于小样本的数字**。
10. **量比在历史重建场景**需要历史日均成交量作为基线；基线不足时该榜单会被隐藏并说明原因。

# ARCHITECTURE — 资金流向指挥中心 AI Edition

> 版本 1.1.0 · 本文档描述**当前源码**的实际架构，与实现一一对应。

---

## 1. 三层架构与职责边界

```
┌──────────────────────────────────────────────────────────────┐
│  Tauri 2.x 桌面外壳（Rust）        tauri/src/lib.rs           │
│  · 创建窗口（系统级全屏）/ 系统托盘 / 生命周期                 │
│  · 单实例检查                                                  │
│  · 启动、监控、终止后端子进程                                  │
│  · 把端口号与访问令牌注入前端                                  │
│  ❗ 不含任何业务逻辑                                          │
└───────────────────────────┬──────────────────────────────────┘
                            │ 启动子进程 + 注入 __CAPITAL_FLOW_PORT__ / __CF_TOKEN__
┌───────────────────────────▼──────────────────────────────────┐
│  React + TypeScript 前端          frontend/src/               │
│  · 只负责渲染与交互                                            │
│  · 通过 HTTP REST 调用本地后端                                │
│  ❗ 不含任何业务计算（涨跌家数、榜单、口径判定全在后端）        │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP REST（127.0.0.1，需 X-CF-Token）
┌───────────────────────────▼──────────────────────────────────┐
│  Rust 后端（Axum + Tokio + Reqwest）  backend/src/            │
│  · 数据采集 / 降级链 / 限流 / 熔断                            │
│  · 业务计算：榜单、涨跌家数、资金口径、事件计数                │
│  · 历史静态分钟库（Parquet + DuckDB）                         │
│  · 本地 SQLite 持久化                                         │
│  ✅ 全部业务逻辑在这里                                         │
└──────────────────────────────────────────────────────────────┘
```

**为什么这样切分**：桌面外壳只做"窗口与进程"，前端只做"显示"，两者都不允许出现
业务规则。任何口径判断（例如"这个数字算不算全市场口径"）都必须能在后端代码里
找到唯一实现。

## 2. 进程模型

| 环节 | 实现 | 说明 |
| --- | --- | --- |
| 启动 | `tauri/src/lib.rs::ensure_backend` | 外壳解析后端可执行文件路径并 `spawn` |
| 端口 | 默认 `47821`，被占用时顺延 | 写入 `cache/port`，前端也读该文件 |
| 令牌 | 后端启动时生成 128 位随机串 | 写入 `cache/token`，外壳读文件并注入前端 |
| 就绪 | 外壳轮询 `/api/health`（免鉴权） | 就绪后才让前端进入主界面 |
| 单实例 | 后端绑定端口前做健康探测 | 已有实例在跑时新实例直接退出 |
| 退出 | 外壳先 `POST /api/shutdown`，再回收子进程 | **不留幽灵进程**；后端在 `logs` 中留"已安全退出" |

后端子进程由外壳持有句柄，窗口关闭 / 托盘退出 / 任务栏关闭都会走同一套回收逻辑。

## 3. 数据流

```
数据源                   采集器                     计算/存储                 API
────────────────────────────────────────────────────────────────────────────────
东财 clist/ulist  ──┐
腾讯 rank/quote   ──┼──► collector/market.rs ──► 全市场股票池(5571)  ──► /api/stocks
新浪 rank/quote   ──┘         │                        │
                              │                        └──► engine/breadth ──► /api/market/breadth
                              └──► engine/ranking.rs ──► 九榜 ─────────────► /api/boards
东财 fflow/kline  ────────► history/preload.rs ──► Parquet 历史库 ──► DuckDB ──► /api/snapshot
新浪 getKLineData ────────► history/preload.rs ──► Parquet 历史库 ──► DuckDB ──► /api/timeline/point
东财/腾讯 板块榜单 ───────► collector/sector.rs ──► SQLite sector_nodes ──► /api/sector/compare
早盘节点快照      ────────► collector/history.rs ──► SQLite snapshots ──► /api/opening
```

**缓存层**：`state.cache`（`cache.rs`）保存内存中的最新值，每项都带
`status / source / updated_at / ttl`，接口返回时统一包装成 `Envelope<T>`。
过期不删，作为"最近有效数据"降级使用。

**降级链**：东方财富 → 腾讯财经 → 新浪财经 → 本地缓存。
每个通道有独立冷却闸门（`state.rs::gate_keys`），互不误伤。

## 5. 历史静态分钟库

```
data/history/
├── series/kind=index/key=1.000001/date=YYYY-MM-DD.parquet      指数分时
├── series/kind=market_flow/key=1.000001/date=YYYY-MM-DD.parquet 大盘资金流
├── minute/code=600519/date=YYYY-MM-DD.parquet                  单只股票分钟
└── minute_market/date=YYYY-MM-DD.parquet                       全市场分钟物化视图
```

* 写入：`parquet_store.rs`，先写临时文件再原子 `rename`，写入前按分钟排序。
* 查询：`duck.rs`，DuckDB 读 Parquet，做分区裁剪 + 谓词下推。
  **所有 `read_parquet` 必须带 `hive_partitioning = false`** ——
  否则 DuckDB 会把目录名 `code=600519` 当成 Hive 分区列并推断为 BIGINT，
  覆盖文件内的 Utf8 `code` 列，导致查询静默返回 0 行。
* 时间轴：一律使用**行情时间**（数据自带的 `minute`），
  绝不使用系统时间或抓取时间。

## 6. 本地 API 安全边界

只监听 `127.0.0.1` 并不足以防止浏览器里的任意网页发起请求，因此：

1. 后端启动生成 128 位随机令牌，写入仅本机用户可读的 `cache/token`；
2. 除 `/api/health` 外**所有**接口都要求 `X-CF-Token` 头；
3. CORS 只允许本程序自身的前端来源，不使用 `Any`；
4. 前端首次请求 401 时会强制重新解析令牌并重试一次（解决启动竞态）。

## 7. 前端结构

```
frontend/src/
├── api/            REST 客户端与类型定义（与后端 DTO 一一对应）
├── components/     通用组件（卡片/图表/表格/状态徽标…）
│   └── home/       首页四个核心模块 + 数据口径条
├── hooks/          usePolled（可见性感知轮询）、后端启动、全屏
├── pages/          8 个页面
├── stores/         zustand 全局状态
├── styles/         主题变量
└── utils/          纯格式化函数
```

**轮询策略**：`usePolled` 在页面不可见时自动暂停；请求失败保留上一次有效数据
并累计失败次数，由 `StatusBadge` 如实展示。

## 8. 关键设计约束（代码评审沉淀）

1. **口径只有一个来源**。股票池只有一个（全市场，本地证券列表 + 批量行情）；
   不存在"活跃股样本"这类由排行榜拼出的有偏池子。
2. **不允许伪造数据**。缺失时隐藏该模块并说明原因，不补 0、不用实时值回填历史、
   不用别的交易日数据冒充当天。
3. **降级必须可见**。通道、覆盖数、缺失原因都要随响应返回并展示。
4. **时间概念不得混用**。系统时间 / 行情时间 / 交易日 / 抓取时间分别字段化。
5. **同一份数据只算一次**。所有派生指标在后端计算，前端只格式化。

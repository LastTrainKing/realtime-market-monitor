# DATA SOURCES — 数据源说明

> 版本 1.1.0 · 本文档记录**实际使用的接口、实测得到的限制、以及各模块的口径来源**。
> 所有"实测"数字都来自本项目在本机的真实请求结果，不是文档推测。

---

## 1. 降级链

```
东方财富（主） ──失败──► 腾讯财经 ──失败──► 新浪财经 ──失败──► 本地缓存
```

* 每条通道有**独立冷却闸门**（`state.rs::gate_keys`）：`eastmoney:clist` /
  `eastmoney:ulist` / `eastmoney:his` / `eastmoney:fflow` / `tencent` / `sina`。
  某个接口失败只冷却它自己，不会误伤同源的其他接口。
* 熔断按**主机**维度，半开状态只放**一个**探测请求通过。
* 多主机不可达时立即停止轮换，避免把网络故障当成单机故障反复重试。

## 2. 东方财富

| 用途 | 主机 | 接口 |
| --- | --- | --- |
| 榜单 / 批量行情 | `push2.eastmoney.com` 及多镜像（`1.` `82.` …） | `/api/qt/clist/get`、`/api/qt/ulist.np/get` |
| 指数 / 个股分钟 K 线 | `push2his.eastmoney.com` | `/api/qt/stock/kline/get`（`klt=1`） |
| **大盘资金流（分钟）** | **`push2.eastmoney.com`（仅此主机）** | `/api/qt/stock/fflow/kline/get`（`klt=1`） |

**实测要点（勿随意改动）**

1. **`fflow/kline` 只在 `push2` 主机可用**。用 `push2his` 会返回 `rc=0` 且
   `klines` 为空数组 —— 早期实现正是用了 `his_hosts`，导致资金曲线长期为空。
2. **字段顺序**：`时间, 主力净流入, 小单, 中单, 大单, 超大单`，
   且满足 `主力 = 大单 + 超大单`（已用归档样本验证：15:00 时
   `-21.75 + (-37.51) = -59.27` 亿 = 主力净流入）。
3. **该接口返回的是累计值**（09:31 到 15:00 单调累积），
   **不需要也不允许**再由程序累加。
4. `clist` 的 `pz` 有服务端上限（个股列表实测约 100 条/页），
   因此**必须按 `data.total` 翻页取全**。

**指数 secid 对照**

| secid | 指数 |
| --- | --- |
| `1.000001` | 上证指数 |
| `0.399001` | 深证成指 |
| `0.399006` | 创业板指 |
| `1.000300` | 沪深300 |
| `1.000688` | 科创50 |
| `0.899050` | 北证50 |

**市场判定**：`0` = 深市，`1` = 沪市，`2` = 北交所。
注意 **北交所 `920xxx` 与沪 B `900xxx` 都以 9 开头，必须分开判断**
（早期 `market_of("920xxx")` 返回 1，把北交所判成了沪市）。

## 3. 腾讯财经

| 用途 | 主机 | 接口 |
| --- | --- | --- |
| 板块榜单 | `proxy.finance.qq.com` | `/cgi/cgi-bin/rank/pt/getRank` |
| 个股榜单 | `proxy.finance.qq.com` | `/cgi/cgi-bin/rank/hs/getBoardRankList` |
| 实时行情 | `qt.gtimg.cn` | `/q=` |
| 分时数据 | `web.ifzq.gtimg.cn` | `/appstock/app/minute/query` |

**实测限制（重要）**

腾讯板块榜单 `count` 参数的**服务端上限是 200**：

```
count=100  → 53,350 字节（正常）
count=200  → 106,205 字节（正常）
count=250  → 83 字节（服务端直接拒绝）
count=300  → 83 字节
count=400  → 83 字节
count=500  → 83 字节
```

因此 `RANK_MAX_COUNT = 200`，且请求失败时**按条数递减重试**（200 → 100 → 50）。
曾因把请求值调到 500 导致整条腾讯板块通道失败、一个板块都拿不到。

**覆盖度差异**：东方财富概念板块有 **400+** 个，腾讯通道单次上限 200，
所以降级时板块总数约 231（行业 31 + 概念 200）。界面会显示来源与覆盖数，
并在概念数偏少时**显式告警**。

## 4. 新浪财经

| 用途 | 主机 | 接口 |
| --- | --- | --- |
| **多日分钟 K 线** | `quotes.sina.cn` | `CN_MarketDataService.getKLineData` |
| 个股榜单 | `vip.stock.finance.sina.com.cn` | `Market_Center.getHQNodeData` |
| 实时行情 | `hq.sinajs.cn` | — |

**`getKLineData` 是本项目唯一能拿到多日分钟数据的通道。**

实测 `datalen` 硬上限 **1023** 点，按周期换算的可回溯交易日数：

| 粒度 | 单次可覆盖 | 是否满足 90 天 |
| --- | --- | --- |
| 1 分钟 | **4 个交易日** | ✗ |
| 5 分钟 | 21 个交易日 | ✗ |
| 15 分钟 | 63 个交易日 | ✗ |
| 30 分钟 | **127 个交易日** | ✓ |
| 60 分钟 | 255 个交易日 | ✓ |

**结论：90 天的 1 分钟数据在物理上不可能一次取到**，只能由程序逐日累积。
把配置项 `history_granularity` 改为 `30` 可立即获得 127 个交易日的覆盖。

字段：`day / open / high / low / close / volume / amount`，时间轴天然正确
（含午休断点 11:30 → 13:01，不含任何非交易时段时间点）。

## 5. 各模块的口径来源

| 模块 | 数据来源 | 口径 |
| --- | --- | --- |
| ① 指数分时 | 新浪 `getKLineData`（历史） | 真实分钟点位；以昨收为基准 |
| ② 主力资金累计曲线 | 东财 `fflow/kline`（历史库） | **接口本身即累计**，程序不做累加 |
| ③ 板块流入流出对比 | 盘中实时缓存（并落盘）；非盘中读持久化快照 | 当日定稿快照，非分时序列 |
| ④ 时点数据面板 | 与②同源同分钟 | 累计值 |
| 涨跌家数 / 涨停跌停 / 成交额 | 全市场股票池（本地证券列表 + 批量行情） | 全市场，缺失时标注不完整 |
| 九榜 | 全市场股票池 | 全市场排序 |
| 个股精选 | 九榜事件（事件驱动计数） | 上榜次数，非刷新次数 |

**股票池只有一个**：本地证券列表 + 批量行情，实测 **5571 只**，
在东财、腾讯、新浪三条通道上都能取全。
历史上曾有第二个"活跃股样本"池（排行榜拼出，上限 1200 只），
**已彻底移除** —— 排行榜池按成交额/换手率排序，属于**有偏样本**，
用它算涨跌家数会系统性失真。

## 6. 尚未实测确认的事项（NOT TESTED）

| 事项 | 状态 | 说明 |
| --- | --- | --- |
| 东财 `fflow/kline`（`secid=1.000001`）覆盖范围是**沪市**还是**沪深两市** | **NOT TESTED** | 本机网络对东财 API 完全阻断（`curl` 任意 API 路径 exit 56，而公网与腾讯正常）。因此界面文案只写"东财大盘资金流"，**不写"两市"**，避免给出未经核实的口径 |
| 东财概念板块的准确总数 | **NOT TESTED（本机）** | 只能确认"400+"这一量级（由用户与公开信息给出），本机无法实测；但代码已改为按 `data.total` 翻页取全，**运行时以接口声明的总数为准**，不依赖硬编码 |
| 腾讯板块接口上限是否会变化 | 已知会变 | 已实现递减重试兜底；单测锁住当前实测值 200 |

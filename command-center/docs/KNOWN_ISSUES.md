# KNOWN ISSUES — 已知问题与限制

> 版本 1.1.0 · 本文档只列**真实存在**的限制，并区分"物理限制 / 环境限制 / 未实现 / 未验证"。

---

## A. 数据源物理限制（无法通过改代码解决）

### A1. 1 分钟历史数据最多只能回溯 4 个交易日

* **原因**：新浪 `getKLineData` 的 `datalen` 硬上限为 **1023 点**（实测）。
* **各粒度可回溯天数**（实测）：

  | 粒度 | 可回溯 | 满足 90 天 |
  | --- | --- | --- |
  | 1 分钟 | 4 个交易日 | ✗ |
  | 5 分钟 | 21 个交易日 | ✗ |
  | 15 分钟 | 63 个交易日 | ✗ |
  | 30 分钟 | **127 个交易日** | ✓ |
  | 60 分钟 | 255 个交易日 | ✓ |

* **影响**：**90 天的 1 分钟数据在物理上不可能一次取到**。
* **应对**：程序逐日累积；把配置项 `history_granularity` 改为 `30`
  可立即获得 127 个交易日的覆盖。
* **不是缺陷**：这是数据源能力上限，程序已如实上报（`/api/history/status`
  的 `granularity_capability` 字段就是实测值）。

### A2. 板块没有历史分时序列

* **原因**：数据源不提供历史交易日的板块分钟资金流。
* **影响**：首页模块③展示的是**当日定稿快照**，不是分时曲线。
* **应对**：接口 `note` 与界面都明确标注；非交易时段从本地持久化快照读取。

### A3. 板块覆盖数取决于通道

* 东方财富概念板块有 **400+** 个；降级到腾讯时其榜单接口**单次上限 200 条**
  （实测 250 及以上被服务端直接拒绝），因此降级时板块总数约 231。
* **应对**：界面显示"来源通道 + 共 N 个板块（行业 X / 概念 Y）"，
  概念数偏少时**显式告警**，不把"只覆盖一部分"当全量。

### A4. 东财接口在本机不可达

* 实测：`curl` 到 `push2.eastmoney.com` 的任意 API 路径返回 `exit 56`，
  而公网（baidu.com）与腾讯接口均返回 200。
* **影响**：本机上大盘资金流、板块、个股资金明细等东财通道全部走降级。
* **不是程序缺陷**：程序按设计自动降级并如实标注来源。

## B. 尚未实现的功能

### B1. 分钟成交量未做"大单 / 中单 / 小单"分级

* **原因**：缺少逐笔成交数据，任何此类分级都只能是**估算**。
* **现状**：代码中**不存在**"把分钟成交量伪装成大单"的逻辑。
  资金分项只用数据源直接给出的超大单/大单/中单/小单字段。
* 若将来实现，必须标注为 `ESTIMATED`。

## E. 使用注意

1. **升级前请先退出正在运行的程序**，否则安装文件被占用可能替换失败。
2. **首次启动约需 75 秒**才能展示全市场统计（其中证券列表刷新约 28 秒）。
   这段时间界面如实显示"全市场扫描进行中"，**不会**退回小样本数字。
   证券列表本地缓存 3 天，之后启动很快。
3. **数据目录与程序目录分离**（`%APPDATA%\CapitalFlowCenter` 与
   `%LOCALAPPDATA%\资金流向指挥中心`），升级只需替换程序，不影响数据。
4. **不要删除 `%APPDATA%\CapitalFlowCenter\data\history\`**：
   这是逐日累积的历史分钟库，删掉后无法从数据源重新取回早期日期。

### 2.1 第一版工具（`flowtool`）

**用户要求**（01:06）：

> 「请独立开发一个可在我本机运行、无需登录与上线合规的前后端一体化应用……

> 到了今天早上九点半，就应该是今天盘中的主力资金曲线了」

**交付**：`outputs/flowtool/` —— 相对路径自包含，拷走即跑。

| 模块 | 职责 |
|---|---|
| `flowdata.py` | 抓取全市场 1000 个板块 1 分钟资金流 |
| `universe.py` | 板块池清洗（1000 → 427） |
| `salience.py` | ★ 分析内核（辨识度 / 聚类 / 时间轴） |
| `render.py` | 四张图（发散曲线 / 辨识度时间轴 / 主角更替 / 阶段对比） |
| `report.py` | HTML 报告 |
| `intraday_flow.py` | 命令行入口 |

**辨识度公式**：体量 34% + 速度 28% + 排名跃迁 16% + 持续性 12% + 异动 z 10%
—— 全部用**横截面分位**而非绝对金额。

**当时踩的 7 个坑**（已固化进 skill）：
1. 主域 `push2.eastmoney.com` 被限流 → 必须多域名故障转移
2. 本机代理不稳 → `session.trust_env = False` 直连优先
3. **统计桶污染**：融资融券/MSCI/沪股通等属性桶会霸榜（首版 Top 全是「融资融券 -303亿」）→ 剔除后 1000→427
4. **不做市场中性化** → 相关聚类会把 400 板块聚成一个假簇（实测 123 成员、簇内平均相关仅 0.03）
5. **union-find 单链会传递串簇** → 改用「以龙头为种子的贪心聚类」
6. **末端标签避让要在显示像素上做**，数据坐标设间距会叠字
7. matplotlib 中文需设 `font.sans-serif` + 关 `axes.unicode_minus`

## 五、Day 4（09-21 上午）启动提速与时间同步

### 5.1 v1.2.3：启动 5.2s → 1.8s，刷新 5min → 30s/10s

> （10:07）「优化算法，第一个，每次点进exe延迟太高，差不多要5s，
> 第二个，盘中抓取数据不是很频繁，要求30秒甚至10秒一抓」

**先量化（关键：结论与直觉相反）**：
```
exe 冷启动 5.05s 拆解（读 exe 自写日志时间戳，非估算）：
- onefile 解包 1.64s + import ~1.0s  ← 在 Python 代码之前，代码碰不到
- 交易日历联网 894ms（占 40.7%）    ← 真·可优化
- 数据/特征 ~1.0s                    ← 已接近下限
```
> ★ **核心认识**：5 秒里最大一块是**打包形态**决定的，**优化算法对它无效**。

**四项改动**：
1. **onefile → onedir**：3.67s → **1.84s**（A/B 各 5 次取中位）
   - 附带：onefile 强杀会残留 `%TEMP%\_MEI*`，实测累积 **30 个 / 3.8GB**
2. **交易日历磁盘优先**：894ms → **0.8ms**
3. **批量快照增量刷新**：`ulist.np/get` 一次问 200 个板块 → 1000 次请求变 5~6 次；全量 3541ms → 增量 **408ms**（8.7×）
4. **刷新周期可配**：10s / 30s（默认）/ 1min / 5min

> ★ **反直觉**：周期缩短后请求量**大降** —— 10 分钟从 1000 次降到 120 次（**-88%**）。

> （10:44）「**你在重复开**」← ★ 用户抱怨 exe 窗口反复弹出。
> **这条改变了后续所有验证方式**：改用日志读取 / 纯文件 / `--shot` 离屏自检。

### 5.2 v1.2.4：曲线只画到 10 点多

> （11:21）「数据源的时间戳已更新为正确时间，但图表渲染未能同步：**曲线只画到 10 点多**…
> 判断曲线只画到 10 点多是因为曲线对应的数据直到十点多还是
> **曲线的数据已经到了十一点多但是没有对上横坐标**」

**四条独立证据定位**：
| 证据 | 实测值 |
|---|---|
| 面板最新分钟 | **11:17**（分钟序号 106） |
| 曲线像素反推落位 | 第 **40** 格 ≈ **10:11** |
| 差值 | 106 − 40 = **66 分钟** |
| 实时接口直采 | **119 分钟逐分连续、零缺口** |

→ 数据源有、接口给得出、图上没有 ⇒ **问题 100% 在画图侧**。

**根因：两套坐标系在同一根轴上打架**
```python
画曲线（旧） ax.plot(range(len(s)), s)   # x = 数组下标 0,1,2,…
标刻度（旧） _minute_index(lab)          # x = 分钟序号 09:31=0 … 15:00=239
```
只有面板**一分钟都不缺**时两者才重合。而增量刷新每次只追加「当前这一分钟」，
程序没开着的那几分钟**永久缺失** → 41 个点被压缩到左侧 17%。
★ **偏差累积，不会自愈。**

**修复三件套**（缺一不可）：画图侧 `_x_positions()` + 交互侧 `_row_at_x()` + 数据侧缺口守卫。

> ★ **顺带挖出更深的 bug**：面板里出现**不可能存在的刻度 `11:43`**
> —— 11:31~12:59 是午休，A 股不产生分钟数据。
> 旧代码 `datetime.now().strftime("%H:%M")` 直接当行标签写，
> 午休期间每刷新一次就塞一行假刻度，`_minute_index("11:43")` 返回 `None`，
> **一个脏点带偏整条时间轴**。

1. `_time_key(hm)`：`'HH:MM'` → `HH*60+MM`（**不能用字符串比较**：`'9:35' > '10:00'` 字典序成立；

3. **`timeline_summary` 新增 `topn`** ← ★ **最隐蔽的连带炸点**
4. 界面文案 + **第四份 JS 副本**（差点漏掉）

> ★★ **改排序 = 改截断**：旧代码 `timeline_summary(F)[:24]` 依赖强度序才有
> 「取最强 24 条」语义。改时间序后**同一行代码静默变成「取最早的 24 条」**：
> 尾盘整段消失、行数还是 24、**不报错、不缺行**。
> 实测误写 `[:18]` 最晚只到 10:27，**丢掉 63 分钟尾盘**。

> ★★ **第四份副本是 JS 重写**（`single_file_app.html` 的 `keyNodes()`），
> 在另一个目录、另一种语言 —— **搜 `timeline_summary` 永远找不到它**。
> 教训：**修「某个函数」要按语义找，不能按函数名找。**

## 九、关键决策与其理由（为什么是这样）

| 决策 | 理由 |
|---|---|
| **PySide6 而非 Electron/WebView** | 用户明确要求「真原生，不要套壳」；无浏览器内核 |
| **onedir 而非 onefile** | onefile 每次启动解包 69MB（1.64s）**且发生在 Python 代码之前**，任何代码优化碰不到；且强杀会残留 `%TEMP%\_MEI*`（实测 30 个 / 3.8GB） |
| **专用 venv `native_env`** | 用装了 pandas 的通用环境打包，matplotlib 的可选依赖会把 pandas/lxml/fsspec 一并收进 exe（**69.6MB → 92.5MB**） |
| **数据源只用东方财富公开接口** | 用户要求「无需登录与上线合规」；只读公开行情 |
| **辨识度用横截面分位而非绝对金额** | 绝对金额会被大盘系统性影响；分位可比 |
| **剔除统计桶** | 融资融券/MSCI 等属性桶覆盖大半个市场、结构性常年净流出，不剔除会霸榜 |
| **市场中性化后再聚类** | 不中性化 → 400 板块聚成一个假簇（123 成员、簇内相关仅 0.03） |
| **>6 分钟缺口才全量重抓** | 取 6 是为了**不误伤 5 分钟档**的正常刷新 |
| **向 Qt 要字符串而非 OCR** | 本机无 OCR 依赖；模板匹配认数字不可靠；Qt 的字符串是**同一份数据** |
| **改变诊断方式为离屏** | 用户抱怨「你在重复开」→ 改用日志 / 纯文件 / `--shot` 自检 |

## 三条最容易踩的坑（务必先知道）

### ① 同一逻辑有 4 份实现 / 6 个文件 —— 改一处必须同步全部

```
work/native_build/core/salience.py                    ← 打包源（★ 主副本）
  ↳ dist_v125_onedir/.../_internal/core/salience.py   ← 打包产物内
  ↳ %LOCALAPPDATA%\FlowLiveNative\_internal\core\...  ← 已部署
outputs/flowtool/salience.py                          ← 独立工具副本
~/.workbuddy/skills/astock-intraday-flow-salience/scripts/salience.py   ← 技能副本
templates/single_file_app.html / 资金流向看板.html    ← ★ JS 重写（另一种语言！）
```

> **修「某个函数」要按语义找，不能按函数名找** ——
> JS 那份搜 `timeline_summary` 永远找不到。

### ② 改排序 = 改截断

任何按序输出的函数，**改排序键前先搜所有 `[:N]` / `.slice(0,N)`**。
本项目就因此踩过坑：`timeline_summary(F)[:24]` 从"取最强 24 条"
静默变成"取最早 24 条"，**尾盘整段消失但行数不变、不报错**。

### ③ 数据层有序 ≠ 屏幕有序

`on_data → fill_table → QTableWidget`，任何一层二次排序都会破坏。
验证必须抵达**屏幕层**（向 Qt 要字符串，不要读像素做 OCR）。

## 五、完整性自评

| 维度 | 结论 |
|---|---|
| 版本标识覆盖 | 原生版 18 个 + 指挥中心 3 个 = **21 个** |
| 有可运行 EXE 的版本 | 原生版 16 个 + 指挥中心 3 个 |
| 有源码的版本 | 原生版 4 个（v1.2.5 / v2.0.2 / v2.0.2b / v3.0.6）+ 1 个过渡快照（v2.0.1~2.0.2）+ 指挥中心 1 个（v1.1.0） |
| 有源码但无独立快照 | 原生版 v2.1.0 ~ v3.0.5 共 7 个（共用 `app_main_v203.py`） |
| 无任何产物 | v2.0.5 |
| 有产物但未部署 | v3.0.3 |
| 归属待核实 | v2.0.1（源码）、v3.0.4_104344、v3.0.2_100741 |

**为什么源码覆盖率不高**：原生版主程序是**单文件**（`app_main_v203.py`，503 KB），
v2.1.0 → v3.0.6 一直在同一文件上就地修改，作者没有为每个版本留源码副本；
只有 PyInstaller 每次构建时的 `_internal/core/` 里带着当时的内核副本，
而那些目录按「构建产物」被排除。这是**原始材料的客观限制**，不是归档遗漏。

## 六、如何自行复核本表

所有结论都可以用 U 盘原始文件复核（原始文件未做任何修改）：

```powershell
# 1) 列出全部版本目录及其 版本.txt
Get-ChildItem "D:\资金流向项目\04_四形态交付包_20260923\资金流向_四形态交付包\03_桌面版_exe\历史版本" -Directory |
  ForEach-Object { "$($_.Name) => " + (Get-Content "$($_.FullName)\版本.txt" -ErrorAction SilentlyContinue) }

# 2) 逐版本 EXE 哈希
Get-ChildItem "…\历史版本" -Recurse -Filter *.exe |
  ForEach-Object { "$($_.Length)`t$((Get-FileHash $_.FullName -Algorithm SHA256).Hash)`t$($_.FullName)" }

# 3) 构建产物对照（判定二进制归属）
Get-ChildItem "D:\…\flowlive_v201\build" -Recurse -Filter *.exe -Depth 2 |
  ForEach-Object { "$($_.Length)`t$($_.FullName)" }
```

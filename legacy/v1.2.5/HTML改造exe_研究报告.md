# 把电脑端 HTML 应用改造成独立 exe 软件 —— 可行性与方案研究报告

> 调研日期：2026-09-19　|　对象：资金流向实时看板（单文件 HTML，约 144 KB）
> 本报告的方案体积、下载量、成功率等数据均为**本机实测**，非估算。

---

## 一、结论摘要

**可行，且已经做出来了。**

推荐方案：**内置本地 HTTP 服务 + 调用系统 Edge 的 `--app` 应用窗口模式**，
用 PyInstaller 打包成单文件 exe。

- 产物：`资金流向.exe`，**7.8 MB**，双击即用
- 实测结果：启动后本地服务正常响应（HTTP 200，144296 bytes），
  Edge 应用窗口成功拉起（msedge 进程 6 → 14），exe 进程存活
- 依赖：仅需要系统已安装 Edge（Windows 10/11 标配）

同时，**不推荐 pywebview 内嵌 WebView2** 这条看起来最"原生"的路——
本机实测它在加载 URL 时存在兼容性缺陷（详见第三节）。

## 三、方案对比（含实测）

### 方案 A：内置 HTTP 服务 + Edge `--app` 模式 + PyInstaller ⭐ 推荐

**做法**：exe 启动时起一个只监听 127.0.0.1 的静态服务提供页面，
再用 `msedge.exe --app=http://127.0.0.1:<port>/index.html` 打开应用窗口。

| 维度 | 情况 |
|---|---|
| 实测体积 | **7.8 MB** |
| 实测成功率 | ✅ 通过（本地服务 200、Edge 窗口拉起、进程存活） |
| 额外下载 | 无（Python/PyInstaller 已就绪） |
| 额外依赖 | 系统 Edge（Win10/11 标配） |
| 打包耗时 | 约 20 秒 |

**优点**
- 体积极小，构建快，链路每一环都在本机验证过
- **页面运行环境与现在完全一致**（同为 Chromium 内核、同为 http 来源），
  不需要重新验证业务逻辑
- 用固定 `--user-data-dir` 后，localStorage（面板缓存 + 30 交易日归档）稳定持久
- `--app` 模式无地址栏无标签页，任务栏有独立图标，观感等同原生软件

**缺点**
- 「独立」是相对的：仍依赖系统 Edge。Edge 被卸载/被策略禁用时会退化
  （已在代码里做了兜底：找不到 Edge 就用默认浏览器打开）
- 相比内嵌方案，多了一个本地端口（只绑 127.0.0.1，不对外暴露）

---

### 方案 B：pywebview 内嵌 WebView2（Python 路线）—— ❌ 本机不可用

**做法**：Python 直接创建 WebView2 窗口加载页面，PyInstaller 打包。

**实测结果（关键）**：

| 加载方式 | 结果 |
|---|---|
| `create_window(html="<h1>hi</h1>")` | ✅ 窗口就绪，`evaluate_js` 可用 |
| `create_window(url="http://127.0.0.1:port/x.html")` | ❌ `_loaded` 一直不就绪 |
| 同上，`debug=True` | ❌ |
| 同上，`gui="edgechromium"` 显式指定 | ❌ |
| 同上，`gui=None` | ❌ |
| 同上，`private_mode=True` | ❌ |
| 同上，`start()` 不带任何参数 | ❌ |
| `html=` 建窗后用 JS 跳转到本地服务 | ❌ 跳转后窗口失效 |

失败时的固定报错：`WebViewException: Main window failed to start`
（pywebview 内部的 `_loaded` 事件未触发，`evaluate_js` 直接拒绝执行）

**结论**：这不是参数配置问题——**五种 `start()` 组合全部失败**，
属 pywebview 与本机 WebView2 Runtime 153.x + pythonnet 的兼容性缺陷。

**为什么不能退而求其次用 `html=` 内联模式**：
该模式下页面来源是 `about:blank`（不透明来源）→
跨域 `fetch` 会被 CORS 拦、`localStorage` 无法持久化 →
**行情取不到、30 交易日归档会丢失**，对本项目不可接受。

---

### 方案 C：Electron（Node 路线）

| 维度 | 情况 |
|---|---|
| npm 包体积 | 1.1 MB（但只是壳） |
| **预编译二进制下载** | **150.9 MB**（`electron-v44.4.3-win32-x64.zip`，实测查询官方 release） |
| 打包后体积 | 约 150~250 MB |
| 额外依赖 | 无（自带 Chromium，最独立） |

**优点**：最成熟稳定；行为与 Chrome 完全一致；生态与文档最丰富；真正独立（不依赖系统 Edge）
**缺点**：体积是方案 A 的 **20~30 倍**；首次安装需下载 150 MB；对"打开一个看板"而言过重

| 打包后体积 | **约 3~10 MB**（最小） |

## 四、关键限制与风险

### 已识别并已处理

1. **localStorage 持久化**（最高风险项）
   WebView/浏览器默认可能把用户数据放在临时目录，重启后缓存与 30 交易日归档全丢。
   → 方案 A 用固定 `--user-data-dir=%LOCALAPPDATA%\FlowLive\EdgeProfile` 解决。

2. **跨域取数（CORS）**
   `file://` 页面的来源是 `null`，在部分内核/策略下跨域请求会被拦。
   → 方案 A 用 `http://127.0.0.1:<port>` 来源，标准 CORS 生效
   （东财接口会回显 Origin），行为与现在的 `.lnk` 方案一致。

3. **端口冲突**
   固定 8765 可能被占用。
   → 代码里从 8765 起顺序探测到 8804，全占用则让系统随机分配。

4. **exe 关掉后残留后台进程**
   → 用 `subprocess.wait()` 跟随 Edge 进程：Edge 窗口一关，exe 立即退出。

5. **打包后资源路径**
   PyInstaller onefile 会把数据解压到 `sys._MEIPASS`，
   直接按脚本目录找 `www/` 会失败。
   → 统一用 `resource_dir()` 处理两种模式。

6. **未装 Edge 的兜底**
   → 找不到 `msedge.exe` 时退化为调用系统默认浏览器打开，并提示保持窗口运行。

### 剩余风险（需留意）

| 风险 | 影响 | 缓解 |
|---|---|---|
| Edge 被卸载或组策略禁用 | exe 无法以应用窗口打开 | 已兜底到默认浏览器；极端情况下可改用方案 D/E |
| 杀软误报 | 首次运行可能被拦 | PyInstaller 单文件 exe 偶发误报，可加白名单；体积小也降低了嫌疑 |
| 本地端口被别的程序探测 | 理论上局域网不可达（仅绑 127.0.0.1），但本机其他程序可访问 | 影响极小；如需可加一次性 token 校验 |
| 页面首次取数慢 | 打开后约 10~40 秒才有数据 | 与现有行为一致，非新增问题 |

## 五、兼容性与依赖重点（改造时必须注意）

1. **浏览器内核一致性优先于"看起来像原生"**
   本页面依赖 `fetch` 跨域 + `localStorage` + Canvas + 较新的 JS 语法。
   换成不熟悉的 WebView 内核（如旧版 MSHTML / 老 WebView）会直接跑不起来。
   方案 A 复用 Edge 内核，**行为与你现在用的完全一致**，没有迁移风险。

2. **不要用 `file://` 加载**
   来源变成 `null`，CORS 与 localStorage 行为都不可靠。务必走本地 http 服务。

3. **必须固定用户数据目录**
   否则每次启动都是"新用户"，缓存在、归档没了。这是最容易忽略、后果最严重的一点。

4. **PyInstaller 的 onefile 与杀软**
   onefile 模式每次启动会把自身解压到临时目录，偶发被安全软件拦截。
   若遇到，可改 `--onedir`（体积略大、启动更快、误报更少）。

5. **打包时别忘了 `--add-data`**
   页面文件必须显式打进去：`--add-data "www;www"`（Windows 用分号分隔）。

6. **路径与中文**
   路径含中文时，部分老工具会出问题（本项目的 Android 打包就踩过
   `aapt` 不支持非 ASCII 文件名）。本方案全程用 Python 处理，无此问题，
   但 exe 文件名与安装目录建议避免过深的嵌套。

## 六、推荐方案与理由

### 首选：方案 A（本地服务 + Edge --app + PyInstaller）

**理由**：
1. **已验证可用**——不是理论可行，是实测通过
2. **体积最优解**——7.8 MB，是 Electron 的 1/20
3. **零迁移风险**——运行内核与现状完全一致，业务逻辑一行不用改
4. **构建成本最低**——本机工具链现成，20 秒出包
5. **维护简单**——只有约 120 行启动器代码，出问题容易定位

**唯一妥协**：依赖系统 Edge。但 Edge 是 Windows 10/11 的内置组件，
实际可用性与"系统自带 API"同级，且代码已做兜底。

### 备选

- **要完全独立、且能接受 150 MB 以上体积** → 方案 C（Electron）
- **要极致小体积、愿意装 Rust 工具链** → 方案 D（Tauri，可做到 3~10 MB）

### 明确不推荐

- **方案 B（pywebview）**：本机实测在加载 URL 时不可用，
  且其可用模式会破坏跨域与持久化，不要在这条路上投入时间。

# 发布产物说明

## 一、结论：本仓库不包含任何编译产物

**没有任何 `.exe` / `.apk` / `.msi` / `.dll` / `_internal/` 被提交到本仓库。**

这是经过评估的决定，不是遗漏。原因如下。

## 二、为什么不分发二进制

### 2.1 原生版是 onedir 结构，单个 exe 无法运行

PyInstaller 的 onedir 产物是 **exe + `_internal/` 目录**（约 145 MB / 450~520 个文件）。
`_internal/` 里是整个 CPython 3.13 运行时 + PySide6/Qt + matplotlib + numpy。

- 只发 exe（8 MB）→ **打不开**，会报缺 DLL / 缺模块；
- 发完整目录 → 每个版本约 153 MB，21 个版本 ≈ 3 GB，远超代码仓库的合理体积
  （GitHub 建议仓库 < 1 GB，单文件 < 100 MB）。

### 2.2 二进制未签名

所有 exe / 安装包都没有代码签名证书。Windows SmartScreen 会对每个下载者
弹出「未知发布者」警告，安装包还会被部分安全软件拦截。
把未签名二进制放进公开仓库，对使用者并不是「方便」，而是把风险转移给了他们。

### 2.3 分发行为本身会放大接口风险

这些程序的全部功能都依赖对第三方行情接口的请求。**分发得越广，越容易触发限流**，
而且被限的是每个使用者自己的 IP。README 与 DISCLAIMER 已经把这一点说清楚，
分发二进制会让这个风险更容易被忽略。

### 2.4 与授权状态一致

本项目**没有开源许可证**（见 [LICENSE.md](../LICENSE.md)），保留所有权利。
在未授予分发许可的情况下，把二进制作为「官方发布」放出去，与许可状态不符。

## 五、如果将来要发布二进制

建议按以下顺序处理，而不是直接上传：

1. **先补许可证** —— 没有许可证时，任何分发都缺乏授权基础；
2. **签名** —— 至少自签名并公布指纹，让使用者能验证来源；
3. **改用 onefile 或提供安装器** —— 避免让使用者面对 145 MB 的 `_internal/` 目录；
4. **附 SHA256 校验值**，并在 Release 说明里写清楚「需要网络、需要访问第三方接口、
   可能被限流」；
5. **不要在 Release 里承诺「稳定可用」** —— 接口随时可能变。

## 六、GitHub Releases 与 Tags

本次归档**未创建 Release，也未创建 Git Tag**。原因：

- 没有可上传的发布产物（见上）；
- 版本号无法完全可靠地映射到提交（v2.0.3~v2.0.12 无源码、v3.0.4/v3.0.5 归属待核实），
  用 Tag 标注会造成「这个 commit 就是 v2.0.8」的错误印象；
- 版本信息以 [versions/inventory.csv](../versions/inventory.csv) 与
  [docs/version-history.md](../docs/version-history.md) 为准，
  这两个文件本身就是可追溯的版本记录。

**如果将来要打 Tag**，建议只对**源码状态确定**的版本打：
`v1.2.5`、`v2.0.2`、`v2.0.2b`、`v3.0.6`，以及指挥中心 `v1.1.0`。
其余版本只能作为「归档记录」存在，不宜标为正式语义版本。

# 版本元数据

本目录保存**各版本部署目录里的原始元数据文件**，按目录原样保留 ——
它们是最直接的「这个版本当时是什么」的证据。

## 关于 `inventory.csv`

列定义：

| 列 | 含义 |
|---|---|
| `产品线` | FlowLiveNative / CapitalFlowCommandCenter |
| `版本标识` | 版本号，或（无法确认时）可追溯的归档名称 |
| `原始路径` | U 盘中的完整路径 |
| `时间` | 版本日期（来自目录名、`版本.txt`、更新日志） |
| `主要功能（已核实来源）` | **来自项目自带更新日志或源码**，不是按目录名猜测 |
| `与前一版本的区别` | 仅记录可证实的差异 |
| `构建产物` | EXE / 安装包 / 其他产物及字节数 |
| `完整性` | 完整 / 部分 / 缺失 / 待核实 |
| `发布备注` | 新增功能、已知问题、版本标识冲突等 |
| `源码归档位置` | 本仓库内的相对路径，或「—」表示无源码 |
| `EXE_SHA256前缀` | 前 8 位，用于快速比对；完整值见下 |

## 为什么保留 `先看我.txt` / `使用说明.txt`

它们是**部署当时写给使用者的现场说明**，含版本自述（例如
「v2.0.10（现役 · 批注精简+区间极值版）」），是判断版本功能最直接的证据之一，
比事后根据目录名推断可靠。归档时逐字保留，未做任何编辑。

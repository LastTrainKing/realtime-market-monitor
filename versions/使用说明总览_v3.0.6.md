# 资金流向 · 成品使用说明总览

本文件夹收录**可直接使用的成品**，全部免安装、双击即用。

## 1. 最新版（★ 现役主力，Windows 桌面端）

- **桌面快捷方式「资金流向」双击即用**——它固定指向 `exe\最新版\`，
  每次升级后自动就是最新版（当前 **v3.0.5**）；
- 也可直接进 `最新版\` 双击「资金流向原生版.exe」；exe 与 _internal 必须在一起；
- **两级页签：6 个母模块 / 14 个子模块**（v2.1.0 起，原 14 个平铺页签重排归类）：

  | 母模块 | 子模块 |
  |---|---|
  | 总览 | （无子页，单页即总览） |
  | 大盘 | 市场全景 · 开盘检测 |
  | 个股 | 个股异动 · 个股精选 |
  | 资金排行 | 异动雷达 · 辨识度榜 · 行业概况 · 实时榜单 |
  | 板块题材 | 题材聚簇 |
  | 盘中复盘 | 实时事件 · 主角更替 · 阶段对比 · 关键节点 |

  **14 个子模块一个不少**，只做了归类与重排；母模块标签即其下子模块的共同主题。
- 快捷键：母模块 `Ctrl+1`~`Ctrl+6`；母模块内子页 `Alt+1`~`Alt+N`；
  菜单「视图」下同样可跳转。
- v2.1.0 同时做了 **UI 密度压缩**（页边距 8/6/8/8 → 6/4/6/6、卡片间距收紧、
  表格行高 24→22、KPI 卡高度下界 74→62、四页单表撑满整页），
  修掉大片空白区；子页签改用下划线式指示，与顶层实底强调区分。
- **v3.0.1**：新增**第三层面板（孙模块）注册表**（40 个面板全部登记 +
  守恒断言，日志 `panel registry OK: 40 panels all mounted`）；
  子模块「题材簇」改名「题材聚簇」（唯一不符四字规则的子模块）；
  修复「该节点未采集」提示被截断成「该…」的缺陷。
- **v3.0.2**：修掉「该节点未采集（程序未在节点时刻运行）」这个长期痛点，
  改为 **A 打底 + B 兜底** 双通道：
  - **A（打底）开机自启**：已装到启动文件夹（`资金流向原生版.lnk`），
    保证 09:36/09:41/09:46 三个节点时刻程序在跑 → 拿到**真·节点值**；
    管理脚本 `workbuddy\flowlive_v201\tools\make_autostart.ps1`
    （`-Action install|uninstall|status`）。
  - **B（兜底）盘中/盘后补采**：错过节点也不用担心——程序在 09:31~15:00 之间
    任何时刻启动，都会自动补齐尚未采集的节点；补采到的数**一定带标注**
    （卡片标题后缀 + 选择器标注「（HH:MM补采）」），**绝不冒充节点值**。
  - ⚠ **物理边界（必须知道）**：B 补采拿到的是**该时刻的累计值**，
    不是节点时刻的历史值——东财接口只提供"当前累计"，不提供历史分钟快照。
    所以补采数据**可用但不等价**，程序用标注把这个区别摆在明面上。
    真正要节点原值，只有 A（保证节点时刻在跑）能给你。
- **v3.0.5（★ 现行）**：修掉「**资金曲线尾部一条平直横线**」。
  用户报告：「为什么有一段数据，没采集呢，这一段直接是横线了」
  （曲线画到约 10:20 后，一路到 15:00 是一条平直横线）。
  - **根因一（数据层）**：面板由**两个文件**表达 —— `panel_{日}.json` 存时间标签、
    `panel_{日}.npy` 存数值矩阵；两者**读写都不是原子的**。
    盘中界面刷新线程与另一轮刷新并发时，会读到「**新矩阵 + 旧标签**」的组合，
    矩阵行数多于时间标签数（实测可能 240 行 vs 50 个标签）。
  - **根因二（渲染层）**：横轴换算函数在"标签比数据短"时，会给多出来的点
    **凭空续出序号**，一路续到横轴最右端（= 15:00），再叠加缺失值端点外推
    → 尾部就成了一条**平直横线**。
  - **修复**：① 数据读入时按时间标签**对齐截断**并记日志；② 横轴换算改为
    "**有标签才有点**"，不再续假序号；③ 两处绘图路径统一按
    `min(数据长度, 标签长度)` 取用；④ 落盘改为**原子成对写、先写标签后写矩阵**
    （让万一的不一致偏向"少画"而不是"多画"）。
  - **验收**：新增专项回归 `test_flatline_guard.py`（18 项全过）+ 真实数据渲染
    验收 12 项全过；全套回归 **110 项 PASS / 0 FAIL**。
    修复前 `xpos[-3:] = [237, 238, 239]`（拖到 15:00）→
    修复后 `[47, 48, 49]`（止于 10:20），右侧留白为**设计行为**
    （横轴固定 9:30–15:00 全程，盘中数据只到当前分钟就画到当前分钟）。
- **v3.0.4**：彻底修掉「该节点未采集」**残留**问题。分两层根因：
  - **判定被误杀**：原代码用"今天在不在交易日历里"判是否开市，
    但日历只含**已完成交易日**（今天的日线要收盘后才生成），
    导致盘中永远判为"非交易日"→ 采集根本不执行。
    新增 `core/tradingtime.py` 作**时间处理唯一权威**：四层证据链判交易日、
    两级时段模型（盘前/集合竞价/盘中/盘后）、盘中刷新不超过 10 秒、法定节假日过滤。
  - **补采状态机写错（真·算法缺陷）**：程序在盘中启动、当天缺 2~3 个节点时，
    补完**第一个**就把"补采已结束"标志置位 → **其余节点永远补不到**，
    界面长期残留「该节点未采集」。现改为"**当天节点全部采齐**才停止补采"。
  - **实测**（10:08 启动，三节点全缺）：10:11 补 m5 → 10:13 补 m10 → 10:15 补 m15
    （各 1000 板块 / 5900+ 个股），10:15:09 判定"已全部采齐，停止补采"，
    界面缺失节点数 **0**。
  - 同时修复：数据源瞬时限流导致的板块缺列（失败自动补抓）、
    "节点存在但内容为空"被误判为已采集。
- 更早累积的功能（v2.0.3~v2.0.12 全部保留）：开盘检测（5/10/15 分钟节点）、
  个股异动（3 节点 × 3 指标 Top10）、个股精选（九榜计数）、区间极值（吸筹/出货前十）、
  累计曲线右端标注 + 悬停联动；v2.0.12 市场全景四模块严格 2x2 田字格等分。
- 详细说明：`workbuddy\更新日志.md`（逐版改动）、`workbuddy\源码说明.md`（架构与构建）。

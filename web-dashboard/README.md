# 网页版看板（单文件 HTML + Canvas）

同一个产品的**最轻形态**：一个 HTML 文件 + 一个零依赖的本地服务。

## 文件

| 文件 | 说明 |
|---|---|
| `资金流向看板.html` | 单文件看板（约 144 KB），原生 JS + Canvas 重写了整套分析逻辑 |
| `serve.py` | 本地服务（**纯 Python 标准库**），把页面用 `http://127.0.0.1` 发出去，并提供 `/__store` 把 localStorage 镜像成磁盘 JSON |
| `启动看板.bat` | 双击启动 |
| `使用说明.txt` | 原作者的完整使用说明 |

## 运行

```bash
python serve.py
```

或双击 `启动看板.bat`。只监听 `127.0.0.1`，不对外开放。

## 为什么不能直接双击 HTML

`localStorage` 的物理位置在**浏览器自己的 profile 目录**（C 盘），
既不跟着 HTML 文件走，也没法指定存到别处 —— 把 HTML 拷到别的盘，
历史数据仍然留在 C 盘，换台机器 / 清缓存就全没了。

`serve.py` 做两件事：

1. 把页面用 `http://127.0.0.1` 发出去（而不是 `file://` 直开）；
2. 提供 `/__store` 接口，把 localStorage 的每次读写**镜像成磁盘上的明文 JSON**。
   页面侧通过一小段转接层（shim）把 localStorage 换成「内存 + 后台落盘」，
   业务代码一行没改 —— 所有读写照旧，只是数据落到了 `data/`。

所以：**历史数据跟着目录走，不依赖浏览器缓存。**

## 数据存哪

`data/` 下的纯文本 JSON（可直接用记事本打开）：

```
data/ls_flowlive_archive_v1.json   历史交易日归档（滚动保留 30 个交易日）
data/ls_flowlive_panel_v1.json     当日面板缓存（秒开用）
data/ls_flowlive_state_v1.json     上次会话状态
data/ls_flowlive_theme.json        亮色/暗色主题选择
data/_backup/                      每次写入前自动留一份旧版本（保留最近 8 份）
data/_deleted/                     被删除/被覆盖的旧数据留档
data/_writes.log                   写入流水
```

> `data/` **未纳入本仓库**（运行期数据，属行情数据）。
> 首次运行会自动创建。

## ⚠️ 数据来源与风险

页面**直接从浏览器请求** `push2.eastmoney.com` / `push2delay.eastmoney.com`。
这意味着：

- 请求以**你自己的 IP** 发出，不是本地服务代发；
- 没有本地缓存层、没有熔断、没有节流 —— **刷新频率完全由你控制**；
- 网页版的请求控制能力**远弱于**原生桌面版。

**请先读 [../docs/data-source-risk.md](../docs/data-source-risk.md)。**
建议：不要高频刷新、不要在多个标签页同时开着、优先在虚拟机内使用。

## 与原生版的关系

网页版是**演进链的第一环**（2026-09-18 ~ 09-21），后续才有 Android APK 与原生桌面版。
同一套分析逻辑在这里是 **JS 重写版** —— 改原生版的内核时必须同步这里，
这是项目里反复踩到的「第四份副本」问题。
